# 修图：检查 → 克制地修 → 连读

一条条漫画出来，大部分问题是局部的：一只手、一个道具、帽子里露出的头发、一个错字。重画整条等于重新抽一次，别的格可能变差，系统性的偏差（比如格子高度被拉平）也不会变。所以先修，修不好再重画。

但修图本身也有代价：每修一次，画面就多一处拼接，光线、笔触、脸都可能悄悄变掉。修得越多，整条越碎。修图是为了让读者读懂、让情绪落下来，不是为了让成图和草稿一模一样。

## 流程
1. **逐条检查**：一条生成好以后调用 review_comic_strip。一组一起生成时，用 check_jobs（until: "any"）等，好一条查一条，不用等整组都画完；好了几条就几条一起查。上一条已经有成图时，把它传给 previous_strip_path，用来检查衔接；character_paths / character_names 传生成时用的角色图和名字，用来查长相和衣服。每个问题都有第几格（panel）、方格坐标（area）、修法（action）和怎么改（fix）。
2. **按门槛筛**（见下面「修图的门槛」）：只有过了门槛的问题才修，其余一律当作不用改。
3. **按 action 分开处理**：
   - **不用改**：跳过，最后跟用户提一句。
   - **字错了**（错字、乱码、缺字、多字）：先用 fix_comic_text 按原文重新排字。它不调用生图模型、不花钱，也不会改出新的错字，不算在修图次数里。框不是白底（拟声词、写在画面上的字）、它报错时，才用 fix_comic_strip 带上 text 修。
   - **修图**、**重画这一格**：攒成一次 fix_comic_strip，同一张图的几处一起修（顺序见下面）。
   - **整条重画**：调用 generate_comic_strip 重画这一条。问题出在草稿时，先用 draft_strip 带上 notes 改草稿。
4. **修完先看提醒**：fix_comic_strip 的 warnings 说某一处「几乎没变」或者「框外的格子有成片变化」，多半是 area 框错了位置。打开 raw_path（模型返回的整张图）看它改在了哪里，按那里重新写 area 再修，不要原样再修一次。
5. **再比较**：对新图（返回的 output_path）再调用一次 review_comic_strip，并且和修之前那一版比。
   - 要修的问题解决了、没有多出新问题：用新版。
   - 没解决，或者多出了接缝、脸变了、字变了、画风不一致：退回修之前那一版，不要接着在坏的版本上修。
6. **最多两轮**：两轮以后还不行，就停下来，把原图和修过的版本都给用户看，问用户怎么办。工具在第三轮会拒绝，除非用户明确要求继续。
7. **整组连读**：一组条漫都生成、修完以后，调用 read_through（strips 按顺序传，同时传 drafts），按 read-through 技能读一遍。连读里根在成图的问题，也要过门槛才修；根在草稿、总剧本的，回去改草稿或总剧本。
8. **交代结果**：最后展示最终版，说明改了哪几处、哪些问题故意没修。原图和每一版都会留着。

用户自己指出问题时（「第3格的手不对」「这句字错了」），不用先检查，直接按下面的办法修，修完再检查。

## 读不懂的问题先找根
检查里 kind 是「读不懂」的问题（不知道这是哪、这个人是谁、这句话指什么、时间跳了没感觉到），先判断根在哪：
- **根在画面**（姑姑只露了腿，没坐到饭桌边）：用修图把交代补进画面，例如「第 2 格画出姑姑走到饭桌边，奶奶给她添碗筷」。
- **根在草稿**（缺交代格、旁白放错了格、特写没有交代它属于谁）：带上问题调用 draft_strip 改草稿，再重新生成这一条。修图补不出一格不存在的交代格。
- **根在总剧本**（定义句、前提句被删了，时间线切换没有安排过渡）：先改总剧本（读 master-script 技能），再改草稿、重新生成。
- **同一组的几条都有这类问题时**：停下来，把问题告诉用户，先一起把总剧本改对，不要一条一条地修图。

## 顺序
- **不同条可以同时修**：几条的修图在一次回复里一起发起，后台会按并发上限排队；同一条一次只修一回，修完检查过再决定下一步。
- **格子比例（版式）先单独修**：传 layout_path，整张都会重新排，不能和局部修改合在一起。检查过新图，再修局部。
- **局部修改**：同一张图的几处可以一次修。几处挤在同一格、彼此有关系时，一起修更好。
- **没修好的那处**：单独再修这一处，不要每次都把所有问题从头来一遍。

## 每一处怎么写（fixes）
- **位置**：panel 和 area 至少写一个。
  - area 用方格坐标（6 列 A–F × 10 行 1–10，盖住整张图），框住**整个要重画的东西**，不只是露出问题的那一点：要把笔抬起来，框整只手和笔；要把苹果的红皮去掉，框整个苹果；要改衣服颜色，框整件衣服。检查给的 area 只框了问题那一点时，自己放大。不要盖到不该动的文字框。
  - 只写 panel 就是整格。写了 panel 时，贴回不会超出这一格；只写 area 时，限在 area 碰到的那几格里。
  - 贴回时，和红框连在一起的那片改动也会一起贴回（框住半只手，整只手也会换成新的），但框外不相连的地方不会。
- **instruction**：写改好以后的样子，一处只说一件事，角色用名字称呼。例：
  - 「我·五六岁的左手平放在大腿上，右手松松地扶着桌沿」
  - 「手机屏幕暗着，是普通的锁屏，没有通话界面」
  - 「帽子盖住全部头发，帽沿下看不到刘海和长发」
- **改颜色、换掉一样东西**：current 写现在画成了什么，instruction 写改成什么，例如 current「浅灰短袖」、instruction「浅蓝短袖T恤，颜色和角色图一样」。这类修改用名字就能说清在哪，传 marks: false，不发坐标方格的标记图；references 附上这个角色的角色图，label 写「角色 我·五六岁（衣服颜色以此为准）」。
- **改字**：用 fix_comic_text（area 框住这个文字框，只框住一部分也能找到；text 写正确的原文，要指定分行时用 ／，不写分行时字数没变就照原来的断法）。area 里有好几个框时它会列出来，用 nth 指定第几个（从上到下、同一行从左到右）。改完看一眼返回的图和 warnings（字号缩小了、字数和原来差得多）。它报错时才用 fix_comic_strip：area 框住那个框，text 写原文，instruction 写「这个旁白框里的字改成 text 的内容」。只改错的那一个框。
- **重画这一格**：只写 panel。instruction 用分镜草稿里这一格的画面指令（可以精简），说清楚这一格要画成什么样。
- **不用写「其他地方保持不变」**：工具会自动加上。

## 给生图模型配哪些图
图 1（原图）和图 2（坐标方格 + 编号红框）工具会自动放；传 marks: false 时不放图 2，位置改用文字说明。其余按需要加：

| 情况 | 加什么 |
|---|---|
| 格子比例和草图差得多 | layout_path：这一条的版式草图 |
| 改到人的脸、手、衣服、头发 | references：这个角色的参考图，label 写「角色 姑姑」这样 |
| 衣服颜色和服装表对不上 | references：角色图，label 写「衣服颜色以此为准」；marks: false，fixes 写 current 和 instruction |
| 前后格要一致（同一机位、道具位置、人物朝向） | reference_panels：作为标准的那一格，label 写以它为准的是什么 |
| 场景要和别处一致 | references：场景图，或者别的条漫 |
| 重画这一格 | 角色参考图；需要时加版式草图 |
| 特殊处理没画出来（コマまたぎ的人物被关进了格子里、断ち切り画成了带框的格、重ねゴマ没叠上去） | layout_path：版式草图；instruction 写清楚要的效果，例如「人物 A 压在第 1–3 格的左半边上，格框在她身后断开」 |

图不要放太多，和这次修改无关的图只会让模型分心。

## keep_outside（只贴回红框附近）
- **默认开着**：生图模型每次都会把整张图重画一遍（连别的格的字都重写），所以工具只把红框附近、以及和红框连在一起的那片改动贴回原图，框外的像素一个不变，别的格的字和脸不会被碰到。
- **要关掉的时候**：调格子比例，或者要整张一起变（比如整体调色）时关掉。传 layout_path 会自动关掉。
- **接缝**：贴回去的边缘偶尔能看出接缝。看得出来时，把范围放大一点再修一次。
- **框错了位置**：模型改对了、但改在了框外时，改动不会贴回，warnings 会提醒。看 raw_path 确认后，按改动所在的位置重新写 area。

## 修图的门槛：不要越修越碎
只有符合下面任意一条，才值得修：
- **读者会读错**：看不出这个人是谁、这是哪里、这句话指什么、时间跳了。
- **连续性断了**：画错人、衣服或发型和前后对不上、人物朝向反了、同ポジ的东西变了位置。
- **情绪的落点没了**：キメゴマ的表演没画出来，或者意思变了（该放松的手攥成了拳）。
- **字错了**：错字、乱码、缺字、多出来的字。

不修的：
- **和草稿的微小出入**：手指的姿势、裁切差一点、道具差几厘米、灯的位置、换行的位置。读者读不出来，就不用改。
- **格子比例差一点**：整体节奏还在就不用动。
- **意思已经到了的表演**：表情的强度、视线的角度略有不同，但情绪读得出来。

上限：
- 一次最多修 3–4 处，工具一次最多收 4 处；一条最多修两轮。
- 同一处修过一次没修好，第二次换一种说法或者放大范围；还不行就接受，或者问用户。
- 宁可留一个小瑕疵，也不要留一个显眼的补丁：一眼看得出的接缝、光线对不上的补丁，比原来的小问题更糟。
- **同一组好几条都要修同一类问题**：这说明根在上游（总剧本或草稿），停下来改上游，不要一条一条地修图。
- **成本**：每修一次就是一次生图调用，和画一条差不多贵。

## 确认模式
fix_comic_strip 和生成条漫一样要用户批准。批准卡片上会列出要修的每一处，所以要写清楚，用户才好判断。
